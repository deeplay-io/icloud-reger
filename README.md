# icloud-codes

Сервис выдачи кодов из писем для пула iCloud-алиасов (Hide My Email).

## Как это работает

- **Родитель** = полноценная iCloud-учётка, залогиненная в своём профиле Dolphin Anty (в одном браузере — один Apple ID). На одного родителя — до 750 алиасов. Сервис ведёт **несколько родителей одновременно**: у каждого свой профиль, своё подключение к браузеру, свои алиасы и своя авторегистрация.
- **Авторегистрация** включается переключателем у каждого родителя отдельно и создаёт алиасы в iCloud со случайными паузами 8–16 минут. Лимит ручного и автоматического создания — не больше 5 запросов за любые 60 минут **на родителя**; родители работают параллельно и друг друга не ждут. Родитель, набравший 750, останавливается (строка помечается «заполнен», сообщение в логе), остальные продолжают; коды заполненного родителя по-прежнему читаются. Расписание и отправленные запросы сохраняются в SQLite, поэтому перезапуск не сбрасывает лимиты. В базу попадают только подтверждённые адреса с сайта.
- **API**: тренер просит код для алиаса `***@icloud.com` → сервис находит родителя алиаса в БД, в профиле этого родителя открывает iCloud-почту, идёт по свежим письмам от новых к старым, находит письмо **на адрес этого алиаса** и вырезает код настраиваемым паттерном. Ответ: `почта:код`.

Вся автоматика в браузере работает **через CDP** (Chrome DevTools Protocol). Профили родителей сервис открывает сам через локальный API Dolphin Anty и держит их подключёнными.

## Требования

- Node.js 20+
- Dolphin Anty с профилем на каждого родителя (либо браузер с remote debugging — тогда профилем родителя указывается адрес CDP)
- В профиле родителя залогинен его iCloud: страница Hide My Email + iCloud Mail

## Быстрый старт

```bash
npm install
npm start                            # сервис без GUI (tsx src/index.ts)
npm run smoke                        # проверка логики без браузера
```

Конфиг: `config.json` в корне проекта (скопируйте из `config.example.json`). Если запустить GUI — он сам создаст `config.json` из примера. Относительные пути `db.file` и `debug.dir` разрешаются от папки, где лежит `config.json`.

## Windows GUI

Electron-приложение: запуск/стоп сервиса, запрос кода в один клик, родители и их настройки, пул алиасов, живой лог. Сервис при этом работает как обычный HTTP API (порт 8787) — тренер может ходить и через него.

Профили родителей подключает сам сервис, без перезапуска и без кнопок: при старте, после добавления родителя или смены профиля, а закрытый профиль — снова в течение 15 секунд (после неудачи — повтор раз в минуту). Порт CDP узнаётся заново при каждом подключении и нигде не сохраняется. Если Dolphin Anty не запущен (его API 127.0.0.1:3001 не отвечает), сервис запускает его: ищет `Dolphin Anty.exe` в `Program Files\Dolphin Anty` и `%LOCALAPPDATA%\Programs`, ждёт готовности API (до 90 с) и первую минуту повторяет открытие профиля, пока Dolphin входит в аккаунт. Запросы к Dolphin идут по одному, чтобы при старте с 15 профилями он не запускался дважды. При нестандартной установке укажите путь в `browser.dolphinPath` в `config.json`. Dolphin запускается независимым процессом и не закрывается вместе с приложением; профили при остановке сервиса только отпускаются, а не закрываются. Профиль, открытый вручную без автоматизации, сервис сам не перезапускает — для этого есть кнопка «Перезапустить профиль». Чтобы сервис перестал открывать профиль, родителя нужно «Отключить».

### Релизы и автообновление

Установщик собирает GitHub Actions ([.github/workflows/release.yml](.github/workflows/release.yml)) по тегу `v*` и выкладывает в Releases репозитория. Выпустить версию:

```bash
npm version minor          # или patch: меняет версию в package.json, делает коммит и тег
git push --follow-tags
```

Workflow проверяет, что тег совпадает с версией, прогоняет тесты, собирает установщик, проверяет его (better-sqlite3 и gRPC-сервис запускаются в Electron) и публикует `icloud-codes-setup-<версия>.exe` с `latest.yml`.

Локально `npm run dist:win` не запускайте: electron-builder пересоберёт `better-sqlite3` в `node_modules` под Electron, и тесты и сервис на Node 22 перестанут запускаться (вернуть: `npm ci`).

Первая установка на сервер — вручную из Releases. Базу переносить не нужно: источник правды — список «Скрыть e-mail» в iCloud.
1. Установите `icloud-codes-setup-<версия>.exe`, выберите «только для меня» (иначе каждое обновление спросит права администратора).
2. «▶ Запустить сервис», затем вкладка «Родители»: для каждого родителя e-mail и ID профиля Dolphin → «Добавить».
3. В настройках родителя (кнопка ▸ в строке) задайте IMAP app-specific пароль для gRPC и включите переключатель авторегистрации.
4. Алиасы родителя загрузятся из iCloud сами: после подключения его профиля, дальше раз в 6 часов. Авторегистрация на новой базе начинает не раньше чем через час: история созданий с другой машины за последний час ей не видна, а лимит Apple — 5 в час.

Обновление с версии 0.2.x: база дополняется сама. Родитель, который был активным, получает профиль Dolphin, метку и состояние авторегистрации из `config.json` — если авторегистрация была включена, она продолжится сама. Прежние «исчерпанные» родители остаются с алиасами и выключенной авторегистрацией: впишите им профиль, если они нужны в работе. Родитель-заглушка `parent@icloud.com` без алиасов отключается.

Дальше:
- Токен для обновлений — fine-grained, владелец `deeplay-io`, только репозиторий `icloud-reger`, право Contents: Read-only. Впишите его в `config.json` как `"update": { "token": "github_pat_…" }` и перезапустите приложение. В установщике и репозитории токена нет.
- Приложение проверяет обновления при запуске и раз в час, скачивает новую версию само, а ставит только по кнопке «Обновить до …»: останавливает сервисы, ставит обновление, перезапускается и снова запускает те сервисы, что работали. Состояние — в чипе «версия», ошибки (например, просроченный токен) — в подсказке чипа и в логе.
- Конфиги и база лежат в `%APPDATA%\icloud-codes\` (`config.json`, `mail-code.json`, `data\codes.db`; кнопки в окне открывают конфиги) и при обновлении не трогаются.
- Сервисы в установленном приложении работают на его же exe (`ELECTRON_RUN_AS_NODE`), Node.js на сервере не нужен.
- Перед запуском сервисов окно выгружает корневые сертификаты Windows в `%APPDATA%\icloud-codes\system-ca.pem` и передаёт их сервисам в `NODE_EXTRA_CA_CERTS`. Это нужно, когда антивирус (Kaspersky и т. п.) проверяет защищённые соединения и подписывает imap.mail.me.com своим корнем: иначе IMAP падает с «self-signed certificate in certificate chain». Если `NODE_EXTRA_CA_CERTS` уже задан в окружении, окно его не трогает.
- gRPC слушает `0.0.0.0:50051`: при первом запуске Windows спросит про доступ к сети. Вместо ответа на запрос создайте правило, пускающее на порт только адреса пилота:

```powershell
New-NetFirewallRule -DisplayName "ICloud Codes gRPC" -Direction Inbound -Protocol TCP -LocalPort 50051 -RemoteAddress <адреса пилота> -Action Allow
```

В окне:
- чипы статуса: сервис / родители в работе (сколько регистрируют, сколько заполнено) / подключённые браузеры / число алиасов / ближайшее создание / gRPC / версия (обновление каждые 5 с);
- запуск и остановка HTTP-сервиса и gRPC-сервиса, кнопки `config.json` и `mail-code.json`;
- «Запросить код» — поле `***@icloud.com`, результат `почта:код` и родитель, в чьём ящике найдено письмо;
- вкладка «Родители»: добавление родителя (e-mail + ID профиля Dolphin) и таблица — браузер, алиасы N/750, переключатель авторегистрации, созданные за час и время следующего создания, IMAP. Кнопка ▸ раскрывает настройки родителя: профиль (сохранить, подключить, перезапустить), IMAP-пароль и прокси (проверить и сохранить, удалить), метка авторегистрации, создание вручную, загрузка из iCloud, последние ошибки, «Отключить» / «Вернуть в работу», «Удалить» (только без алиасов);
- вкладка «Алиасы»: фильтр по родителю, поиск по адресу или метке, постраничный список; «Экспорт всех в CSV» — все алиасы всех родителей (и отключённых) в файл `alias,parent,label` (UTF-8 с BOM, разделитель — запятая) без учёта фильтра;
- вкладка «Лог сервиса»: строки родителей помечены `[e-mail]`, строки gRPC — `[gRPC]`, есть фильтр;
- вкладка «Подключение»: адреса машины для gRPC-клиента, внешний IP по кнопке, готовые команды grpcurl и правила файрвола.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/health` | сводка: родители (в работе, регистрируют, заполнены), подключённые браузеры, число алиасов, ближайшее создание |
| GET/POST | `/code?email=***@icloud.com` | код; ответ `text/plain`: `email:код` (с `format=json` — `{email, code, parent, subject}`) |
| GET | `/parents` | родители с состоянием: браузер, алиасы, авторегистрация, загрузка из iCloud, IMAP |
| POST | `/parents` `{email, profile?, namePrefix?}` | добавить родителя (авторегистрация выключена) |
| PATCH | `/parents/:id` `{profile?, generatorEnabled?, namePrefix?, archived?}` | настройки родителя |
| DELETE | `/parents/:id` | удалить родителя без алиасов |
| POST | `/parents/:id/connect` `{restart?}` | подключить профиль сейчас (restart — перезапустить в Dolphin) |
| POST | `/parents/:id/sync` | загрузить алиасы родителя из iCloud |
| POST | `/parents/:id/aliases` `{name}` | создать алиас в iCloud |
| PUT / DELETE | `/parents/:id/imap` `{password, proxy?}` | проверить и записать / удалить IMAP-пароль в `mail-code.json` |
| GET | `/aliases?parent=&q=&limit=&offset=` | алиасы; без `limit` — весь список массивом |
| GET | `/aliases?format=csv` (`&parent=&q=`) | CSV `alias,parent,label` (UTF-8 без BOM, CRLF): по родителю, внутри по адресу, отключённые родители тоже; `limit`/`offset` не действуют, число строк — в заголовке `X-Alias-Count` |
| POST | `/aliases` `{email, parent}` | добавить существующий адрес, подтвердив его по списку iCloud родителя |
| POST | `/mail/messages` | письма на алиас из профиля его родителя (запасной путь gRPC) |

Пример:

```bash
curl 'http://127.0.0.1:8787/code?email=xyz@icloud.com'
# xyz@icloud.com:482913
```

Коды ошибок: 400 — нет/некорректный email; 404 — алиас не в пуле или письмо не найдено; 503 — профиль родителя алиаса не подключён / селекторы не настроены; 500 — остальное (см. лог и `debug/`).

## gRPC-сервис кодов для пилота регистрации

Отдельный процесс без браузера: читает ящики родителей по IMAP (`imap.mail.me.com`) и отдаёт коды из писем GGPass по контракту [proto/deeplay/mail_code/v1/mail_code.proto](proto/deeplay/mail_code/v1/mail_code.proto) (`MailCodeService.GetCode`). Запускается на том же Windows-сервере, что авторегистратор, кнопкой «Запустить gRPC» в окне приложения; пилот из кластера только обращается к нему за кодами. Порт открыт без TLS и авторизации, поэтому доступ к нему нужно ограничить файрволом (см. «Релизы и автообновление»). Пока в `mail-code.json` пароль из примера, сервис не запускается.

```bash
cp mail-code.example.json mail-code.json   # вписать родителей и их app-specific пароли
npm run imap:probe                          # вход, папки, последние письма
npm run imap:probe -- --alias xyz@icloud.com --days 30 --save   # письма на алиас + .eml в debug/mail-samples/
npm run grpc                                # сервер, по умолчанию 0.0.0.0:50051, без TLS
npm run grpc:call -- --email xyz@icloud.com --kind SIGN_UP --since-minutes 10 --wait 60
```

- Пароль для IMAP — app-specific (account.apple.com → Вход и безопасность → Пароли приложений). Его удобно задавать в окне, в настройках родителя: сервис один раз проверяет вход и записывает пароль (и прокси) в `imap.accounts` в `mail-code.json`; при отказе или сетевой ошибке ничего не сохраняется. gRPC-сервис следит за `mail-code.json` и подхватывает изменения аккаунтов без перезапуска и без обрыва вызовов. После отказа во входе ящик не трогается, пока не сменится его пароль, чтобы не заблокировать Apple ID. Состояние ящиков (подключён / вход не принят / нет связи) gRPC-сервис пишет в `imap-status.json` рядом с `mail-code.json`, окно показывает его в строке родителя.
- Письма только читаются (EXAMINE + BODY.PEEK): не удаляются и не помечаются прочитанными. Смотрятся INBOX и спам (`\Junk`).
- Письмо подходит, если алиас есть в To/Cc/Delivered-To/X-Original-To, оно пришло на сервер (INTERNALDATE) не раньше `sent_after_unix_ms` и относится к запрошенному виду. Берётся самое новое; если код из него не вырезан — FAIL, а не код из старого письма.
- Вид письма (`kinds.CODE_KIND_SIGN_UP` / `CODE_KIND_MFA`): правило по отправителю, теме и тексту; письмо, подходящее под оба правила, не отдаётся. **Текущие правила — черновик**, уточнить по реальным письмам GGPass.
- Адресный поиск: gRPC-сервис читает базу основного сервиса (только чтение; путь передаёт окно в `CODES_DB`, иначе `registry.dbFile` или `./data/codes.db` рядом с `mail-code.json`) и ищет письмо только в ящике родителя алиаса — ящик находится по e-mail или по логину (`user`). Алиас неизвестен, базы нет или у родителя нет своего ящика в списке — поиск во всех ящиках, как раньше. UNKNOWN_MAILBOX — только для чужого домена (`domains`).
- Запасной путь — браузер (`browser` в `mail-code.json`, включён по умолчанию): если родитель алиаса не читается по IMAP (нет пароля, отказ во входе, нет сети), код читается из iCloud Mail в профиле этого родителя через HTTP-сервис этого же окна (`POST /mail/messages`). Родителей с исправным IMAP HTTP-сервис пропускает по своей базе, не открывая браузер. Ограничения: профиль родителя должен быть подключён; только открытая папка (обычно «Входящие», без спама); один проход по почте на алиас не чаще `pollIntervalMs` (15 с), а между проходами повторяется их итог — ошибка прошлого прохода остаётся ошибкой, а не «писем нет»; в одном профиле проходы идут по очереди с созданием алиасов, у разных родителей — независимо; открытые письма становятся прочитанными; время письма — из заголовка с точностью до минуты, поэтому `sent_after` округляется вниз до минуты. Нужны запущенный HTTP-сервис и алиас в базе.
- Есть reflection (для `grpcurl -plaintext`) и `grpc.health.v1.Health` (для проверок доступности).

## Сервис кодов в Kubernetes

Тот же gRPC-сервис (контракт не меняется) работает в кластере без окна, браузера и базы. Приложение на Windows остаётся: регистрирует алиасы, а IMAP-пароли родителей по-прежнему вводятся в окне.

```
пилот ──gRPC 50051 (внутри кластера)──▶ под icloud-codes ──IMAP──▶ imap.mail.me.com
                                              ▲
приложение на Windows ──HTTPS через ingress───┘  PUT /snapshot, GET /status
```

- Приложение раз в `cluster.intervalMs` (10 с) спрашивает у пода `GET /status`. Если у пода не та версия снимка (сменился пароль, появились алиасы, под перезапущен и снимка у него нет), отправляет `PUT /snapshot`: IMAP-пароли и прокси из `mail-code.json` и родителя каждого алиаса из базы. После сохранения или удаления пароля в окне снимок уходит сразу.
- Под хранит снимок только в памяти. Если Windows выключен, коды продолжают выдаваться по последнему снимку. После перезапуска пода ящиков нет, пока приложение не пришлёт снимок, обычно до 10 секунд; в это время GetCode отвечает FAIL с подсказкой.
- Если пароли или база не прочитались, снимок не отправляется: неполный снимок вывел бы под из ящиков. Если под отклонил снимок (например, прокси в `mail-code.json` вписан с ошибкой), тот же снимок не повторяется до исправления или 10 минут. Ошибка видна в чипе «gRPC» и в логе.
- В ответ под возвращает состояние ящиков, и окно показывает его в колонке IMAP, как раньше от локального gRPC.
- Соединение исходящее: на Windows-сервере входящие правила не нужны, нужен доступ к адресу ingress по HTTPS.
- Запасного пути через браузер в кластере нет: родитель без рабочего IMAP-пароля останется без кодов.
- Под — ровно один (`replicas: 1`, `Recreate`): каждый экземпляр держит свои IMAP-сессии ко всем Apple ID. Локальный gRPC на Windows в работе держите остановленным, иначе к Apple ID ходят два клиента; чип «gRPC» об этом предупреждает.

Развёртывание:
1. Образ — `Dockerfile` в корне (`docker build -t <image> .`); workflow `docker` собирает его и проверяет запуск, но никуда не публикует.
2. Манифесты — [deploy/k8s/icloud-codes.yaml](deploy/k8s/icloud-codes.yaml): ConfigMap с `mail-code.json`, Secret с `SNAPSHOT_TOKEN`, Deployment, Service (gRPC 50051 и приём снимка 8080), Ingress только на `/snapshot` и `/status`. Подставьте namespace, образ, адрес ingress и TLS-секрет.
3. Пилот обращается к `icloud-codes.<namespace>.svc:50051` (без TLS).
4. В `config.json` приложения:

```json
"cluster": { "url": "https://<адрес ingress>", "token": "<тот же SNAPSHOT_TOKEN>" }
```

и перезапустите сервис в окне. Связь и время последней отправки — во вкладке «Подключение» и в чипе «gRPC».

В `mail-code.json` пода приём снимка включает `snapshot.port` (0 — выключено, ящики из `imap.accounts`); `snapshot.token` лучше задавать переменной `SNAPSHOT_TOKEN`, `snapshot.maxBytes` — предел размера снимка (32 МБ). Правила писем (`kinds`) берутся из ConfigMap при запуске пода.

## Конфиг (config.json)

- Родители, их профили, метки и переключатели авторегистрации хранятся в базе и ведутся в окне. `parent.email` нужен только для пустой новой базы (добавит этого родителя); `browser.dolphinProfileId`, `browser.cdpUrl`, `generator.enabled` и `generator.namePrefix` читаются один раз — при обновлении с 0.2.x, для родителя, который был активным.
- `browser.dolphinPath` — путь к `Dolphin Anty.exe`, если он установлен не в стандартную папку.
- `browser.hideMyEmailUrl` / `mailUrl` — куда ходить, если вкладки ещё нет.
- `browser.hideMyEmailTabHint` / `mailTabHint` — по какому URL в открытой вкладке её искать.
- Авторегистрация у каждого родителя включается переключателем в его строке: действует сразу, без перезапуска. Выключенная не мешает кодам и загрузке алиасов из iCloud; после включения первое создание — через обычный интервал, а не сразу. Создание начинается, только когда браузер родителя подключён («ждёт браузер» в строке).
- Метка авторегистрации задаётся у каждого родителя (по умолчанию — начало его e-mail). Метки идут по максимальному существующему номеру у этого родителя: `mybox5` → `mybox6`. Адрес назначает iCloud; `@icloud.com` в метку не добавляется.
- `generator.minIntervalMinutes` / `maxIntervalMinutes` — диапазон случайной паузы (по умолчанию 8–16 минут). Ограничение 5 запросов за 60 минут действует независимо от этих настроек.
- Время следующего создания и число созданий за час видны в строке родителя (`GET /parents`). Для работы должны оставаться запущенными сервис и профиль родителя с авторизованным iCloud.
- Ошибка после отправки запроса также занимает слот в часовом лимите: запрос мог выполниться на стороне Apple. Используйте «Загрузить из iCloud» в настройках родителя для подтверждения результата.
- `code.patterns` — **настраиваемые** паттерны вырезания кода (см. ниже).
- `code.freshnessMinutes` — не лезем в письма старше этого возраста (если дата читается).
- `code.maxMessagesToScan` — сколько последних писем проверить по запросу.
- `cluster.url` / `cluster.token` — сервис кодов в кластере (см. «Сервис кодов в Kubernetes»); пусто — не используется. Только `https://`: в снимке пароли от Apple ID (`http://` допустим лишь для 127.0.0.1). `cluster.intervalMs` — как часто сверять снимок (10 с).

### Паттерны кода

Массив, пробуются по порядку; первый, вырезавший 4–6 цифр, побеждает:

```json
{ "name": "kod-digit", "regex": "код[^0-9]{0,12}(\\d{4,6})" }
```

- `regex` — код = capture group 1 (или весь match).
- `mustContain` (опц.) — фильтр «письмо вообще про код», чтобы не резать случайные цифры.

Как только станет известен реальный вид письма от Dolphin Anti / ADS Player — подставьте точный regex.

### Интерфейс iCloud

Создание и импорт используют список «Скрыть e-mail» в iCloud → Функции iCloud+. Ручная и автоматическая регистрация используют один механизм и общую блокировку операций. Кнопки и счётчик находятся по разметке страницы (классы, имена полей), а не по подписям, поэтому язык профиля Dolphin значения не имеет. Старые параметры `generator.selectors` и `generator.intervalMinutes` больше не используются.

Для чтения почты настроены `code.selectors.messageItem`, `body` и `subject`. Чтение учитывает отдельные фреймы iCloud Mail, адрес получателя, дату и уже выданные коды. При изменении разметки Apple эти селекторы и обработчики потребуется обновить. Чтение почты пока рассчитано на русский интерфейс iCloud Mail (заголовки «Кому/Тема/Дата», русские месяцы) и на совпадение часового пояса профиля с часовым поясом компьютера.

## Несколько родителей

- Добавить родителя: вкладка «Родители» → e-mail и ID профиля Dolphin. Сервис подключит профиль, загрузит алиасы из iCloud и покажет состояние в строке; авторегистрацию включите переключателем.
- Родитель набрал 750: его авторегистрация останавливается сама, строка помечается «заполнен». Включите переключатель у другого родителя (или добавьте нового).
- «Отключить» — для родителя, который больше не нужен в работе (заблокирован Apple ID, удалён профиль): сервис не открывает его профиль, не загружает и не создаёт алиасы. Алиасы остаются в базе, коды по IMAP читаются. «Вернуть в работу» — обратно. Удалить можно только родителя без алиасов.
- «Загрузить из iCloud» (и автоматическая загрузка после подключения профиля и раз в 6 часов) приводит алиасы родителя в базе к списку активных адресов «Скрыть e-mail» его профиля: новые добавляются, метки обновляются, отсутствующие в списке удаляются из базы. Пустой список перечитывается повторно, прежде чем очистить алиасы родителя. Если в профиле залогинен другой Apple ID, загрузка останавливается с ошибкой и ничего не меняет.
